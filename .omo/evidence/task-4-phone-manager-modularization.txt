[*.{kt,kts}]
# No rule is disabled: the Kotlin naming convention IS the ktlint default
# (PascalCase files, lowerCamelCase members, UPPER_SNAKE_CASE constants), so
# the standard naming rules run unmodified and fail the build on violation.
#
# The one rule parameter is the documented Compose carve-out. Compose names a
# function that emits UI in PascalCase (it is treated like a factory/type), which
# is the opposite of the camelCase a plain function takes; ktlint's own guidance
# is to exempt `@Composable` functions from function-naming rather than lowercase
# them. The rule stays ENABLED — it still enforces camelCase on every other
# function, and only skips functions annotated `@Composable`.
ktlint_function_naming_ignore_when_annotated_with = Composable

NOTE on the Composable carve-out: this is NOT a re-disable. ktlint 1.5.0's

same). Renaming `@Composable fun AppShell()` to `appShell()` would be wrong.
