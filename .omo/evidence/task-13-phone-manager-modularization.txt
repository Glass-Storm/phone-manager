3. SttFactory -> AppConfig PORT  (design decision D8, behaviour-preservation)
--------------------------------------------------------------------------------
Old signature: class SttFactory(private val config: RuntimeConfigStore, transport)
  ... when (config.sttAdapterKind()) { SttAdapterKind.MOCK -> MockSttAdapter()
        SttAdapterKind.SPEECHMATICS -> SpeechmaticsSttAdapter(SpeechmaticsConfig(config.apiKey(), config.region()), transport) }

New signature: class SttFactory(private val config: AppConfig, transport)
  ... when (config.sttEngine()) { SttEngine.MOCK -> MockSttAdapter()
        SttEngine.SPEECHMATICS -> SpeechmaticsSttAdapter(SpeechmaticsConfig(config.apiKey(), config.region()), transport) }

`diff` of old-vs-new (package/import/KDoc lines stripped) shows ONLY:
  < private val config: RuntimeConfigStore          > private val config: AppConfig
  < when (config.sttAdapterKind())                  > when (config.sttEngine())
  < SttAdapterKind.MOCK / .SPEECHMATICS             > SttEngine.MOCK / .SPEECHMATICS
  + 5 new KDoc lines explaining the port choice
=> MOCK default unchanged; SPEECHMATICS branch unchanged; apiKey()/region() reads
   unchanged; eager-construct/lazy-connect unchanged. Behaviour IDENTICAL.
   (RuntimeConfigStore.sttEngine() maps MOCK->MOCK / SPEECHMATICS->SPEECHMATICS,
    so the persisted value resolves to the same engine as before.)

SttFactoryTest now proves BOTH branches with an in-memory FakeAppConfig:
  default -> MockSttAdapter; SPEECHMATICS -> SpeechmaticsSttAdapter;
  MOCK transcribes offline; no-key SPEECHMATICS -> null (no socket); close no-op.

8. DEVIATION / DECISION RECORD
--------------------------------------------------------------------------------
(a) org.json dependency added to :adapter:jvm. The Speechmatics wire code uses
    `org.json.JSONObject`/`JSONException`. On Android those ship in the platform,
    but a pure-JVM module has no such class; without the artifact the module
    cannot compile. Added `implementation(libs.org.json)` (real org.json 20240303)
    and dropped the Robolectric workaround from the two Speechmatics tests. This
    is a necessary consequence of the mandated split, not a behaviour change.
(b) MemoryDeviceRepository NOT moved to testing/testkit (T13 §4 ordering
    correction). app/.../AppComposition.kt:102 still registers it in PRODUCTION
    for the androidContext == null fallback, which is only deleted in T16.
    It lives in :adapter:jvm here; T16 relocates it.
(c) AdapterHarnessSmokeTest placed in :adapter:android (it exercises the
    Robolectric harness that the Android adapters' tests need).
